# GitNexus — usage rules for this repository

GitNexus is Saakshya's **local code knowledge graph**: it maps symbols, call chains, dependency edges, and execution flows so engineers and AI agents can see the **impact radius** of a change before making it. It runs entirely on your machine.

Full guide: [docs/26-gitnexus-knowledge-graph.md](docs/26-gitnexus-knowledge-graph.md).

## The rule

> **Before any non-trivial code change** (multi-file, refactor, new feature, or backend/database/AI/pipeline change), query the knowledge graph to understand what depends on the code you are about to touch. Then change it. See [CLAUDE.md §6](CLAUDE.md).

In a Claude Code session, prefer the GitNexus **skills** (`gitnexus-exploring`, `gitnexus-impact-analysis`, `gitnexus-debugging`, `gitnexus-refactoring`, `gitnexus-pr-review`) and **MCP tools** (`mcp__gitnexus__context`, `mcp__gitnexus__impact`, `mcp__gitnexus__query`, `mcp__gitnexus__trace`, `mcp__gitnexus__detect_changes`).

## Key commands (from the repo root)

```bash
npx -y gitnexus@latest setup            # one-time: register MCP + skills for your editor
npx -y gitnexus@latest analyze --skills # build / refresh the knowledge graph
npx -y gitnexus@latest status           # is the index fresh?
npx -y gitnexus@latest impact <symbol>  # what breaks if I change this?
npx -y gitnexus@latest context <symbol> # callers, callees, processes
npx -y gitnexus@latest detect-changes   # map current git diff to affected flows
```

## Hygiene

- **Re-analyze** after merging refactors or before starting a large change.
- The generated index directory **`.gitnexus/` is git-ignored** (local, regenerable). Documentation stays committed.
- The graph is currently sparse — the repo is **docs-only** until the first code lands (local-first milestone M0). Re-run `analyze --skills` once code exists so communities and skills generate.

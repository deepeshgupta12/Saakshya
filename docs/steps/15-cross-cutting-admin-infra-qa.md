## Overview
This file owns the six **cross-cutting workstreams** that run *alongside* the phased feature build (siblings [00](00-phase-0-derisk.md)–14) rather than as a single phase. The governing rule is **just-in-time**: nothing here is built upfront. The compliance-critical pieces (the data-health + data-quality dashboards, the compliance/guardrail rule manager, the output-time guardrail pipeline, the AI audit log, the trust-KPI and guardrail test layers) land **early** — they are needed from Phase 1–2 because every user-facing output must pass a compliance design-review gate ([compliance §12](../21-compliance-risk-and-guardrails.md)) and every AI generation must be audited and grounded ([SPEC §6.6](../../SPEC.md)). The heavy infra (Terraform, EKS, full observability) lands **only after** local M5 proves the core ([SPEC §12](../../SPEC.md), [infra §8](../22-infrastructure-devops-and-observability.md)) — the laptop graduation trigger.

Six workstreams:
1. **Admin panel** — built incrementally; data-health/quality + compliance-rule manager early, the rest as their features arrive ([admin](../20-admin-panel.md)).
2. **Compliance & guardrail operations** — output-time enforcement, design-review gate, AI audit logging, blocked-phrase versioning, AI-use disclosure under Mode B ([compliance](../21-compliance-risk-and-guardrails.md)).
3. **Testing & QA** — the test pyramid, stood up early, mapped to SPEC validation gates ([QA](../25-qa-testing-and-release-process.md)).
4. **Infra & cloud graduation** — local-first first, then containerize → Terraform → CI/CD → observability + AI-spend meter → staging/prod → rollback → DR ([infra](../22-infrastructure-devops-and-observability.md)).
5. **Analytics & trust KPIs** — event schema + trust KPIs as launch metrics; Mode-A-safe SEO ([analytics/SEO](../24-analytics-seo-and-growth.md)).
6. **Security & privacy hardening** — auth/RBAC, secrets, encryption, PII/erasure, AI-log security — phased with the relevant features ([security](../23-security-auth-and-privacy.md)).

**The non-negotiable that shapes everything here ([SPEC §0, §12](../../SPEC.md)):** Mode A v1; the local-first build (DuckDB, no cloud) is **validated before** cloud graduation; guardrails enforced **at output time**; AI-use disclosure under Mode B; a compliance design-review gate on **every** user-facing output; evidence-first.

## Exit gate (Definition of Done)
- [ ] The **early** admin modules (data-ingestion monitor, data-quality dashboard, compliance-rule manager) are live and four-eyes-controlled before the first Phase-1/2 user-facing output ships ([admin §2.1–2.2, §2.8](../20-admin-panel.md)).
- [ ] The **output-time guardrail pipeline** (regex + grounding + compliance-review agent) and the **AI audit log** are enforced on every generated/templated output before any AI surface reaches a user ([compliance §9](../21-compliance-risk-and-guardrails.md), [SPEC §6.6, §6.9](../../SPEC.md)).
- [ ] The **test pyramid** (unit/integration/API/scanner-golden/data-quality/AI-grounding/guardrail) is green-gated in CI from Phase 1; visual/E2E/load/security added as the surface grows ([QA §1](../25-qa-testing-and-release-process.md)).
- [ ] **No cloud spend before local M5** retires the three product-killing assumptions ([SPEC §12](../../SPEC.md), [infra §8](../22-infrastructure-devops-and-observability.md)); after graduation, all cloud resources are Terraform-managed with the compliance-critical CI gate enforced.
- [ ] **Trust KPIs T1–T5** are computed nightly and a T1-rise / T4-drop is a stop-the-line alert ([analytics §2](../24-analytics-seo-and-growth.md)).
- [ ] Security controls (auth, RBAC four-eyes, secrets, encryption, PII/erasure, AI-log immutability) are in force for each feature as it ships, per the per-change security checklist ([security §9](../23-security-auth-and-privacy.md)).
- [ ] Every state-changing admin action and every compliance/scanner/prompt change is on an **immutable, four-eyes** audit trail ([admin §3](../20-admin-panel.md), [compliance §10](../21-compliance-risk-and-guardrails.md)).

## Workstream: Admin panel (incremental, RBAC-gated)
**When:** RBAC + data-health + data-quality + compliance-rule manager land **early (Phase 1–2)**; prompt manager + AI audit viewer with the AI layer (Phase 2); scanner-rule manager with scanners (Phase 1, hardened Phase 2); user/subscription/news-source managers with accounts/news (Phase 2); backtest monitor (Phase 4); system-health with cloud graduation (post-M5). · **Backend dep:** RBAC `can(actor, action, resource)` service, the versioned tables (`pipeline_runs`, `data_quality_findings`, `scanner_rules`, `prompt_versions`, `compliance_rules`, `ai_generation_audit`), four-eyes enforcement on publish ([admin §1, §2](../20-admin-panel.md)) · **Frontend dep:** `/admin/*` console (after the thin UI from [01-local-mvp-foundation.md](01-local-mvp-foundation.md) / Next.js graduation; `disallow` in robots, WAF-restricted) · **Data dep:** the as-of-versioned store and pipeline events from [01](01-local-mvp-foundation.md)/[02](02-indicators-and-scanners.md)/[04](04-ai-explanation-layer.md)

### Steps
- [ ] 1. **RBAC first (Phase 1).** Build the five-role matrix (super-admin, data-admin, compliance-officer, support, read-only) **as data, not hardcoded**; expose `can(actor, action, resource)`; enforce the JWT `role` claim server-side; add the **four-eyes invariant** (author ≠ approver) on every `*/publish` endpoint even for super-admin ([admin §1](../20-admin-panel.md), [security §2](../23-security-auth-and-privacy.md)).
- [ ] 2. **Data-ingestion monitor — `/admin/data-health/ingestion` (Phase 1, early).** Per-run/per-stage timeline (ingest → normalize → corp-action adjust → indicators → scanners → news → AI → brief) with status, duration vs overnight budget, re-run/retry/quarantine actions; every run reproducible by as-of version ([admin §2.1](../20-admin-panel.md), [SPEC §6.2, §8](../../SPEC.md)).
- [ ] 3. **Data-quality dashboard — `/admin/data-health/quality` (Phase 1, early).** Surface the SPEC §6.2 checks (missing candles, abnormal jumps, duplicates, delisted, volume sanity), the corp-action reconciliation panel + second-source status ([SPEC §6.1](../../SPEC.md)), the per-symbol data-confidence indicator, and the **detect → quarantine → correct → re-emit** board. Quarantine **suppresses** dependent AI summaries — never a guess ([admin §2.2](../20-admin-panel.md)).
- [ ] 4. **Compliance-rule manager — `/admin/compliance` (Phase 1–2, early & safety-critical).** The versioned blocked-phrase/pattern list + neutralization swap table + `block`/`regenerate`/`warn` severities; a **test console byte-identical to runtime Stage-1** ([compliance §9](../21-compliance-risk-and-guardrails.md)); the **Tier-1 floor is non-removable / non-downgradable by any role**; author ≠ approver on publish; active version ID stamped into the AI audit log ([admin §2.8](../20-admin-panel.md), [SPEC §3.3, §6.9](../../SPEC.md)).
- [ ] 5. **Stock-master + sector mapping — `/admin/stock-master[/sectors]` (Phase 1).** Symbol/ISIN/exchange/listing-status registry; symbol-alias map feeding news→symbol ([SPEC §6.4](../../SPEC.md)); **delisted-name retention** for survivorship control ([SPEC §6.3](../../SPEC.md)); effective-dated sector taxonomy so historical sector scores stay reproducible ([admin §2.3–2.4](../20-admin-panel.md)).
- [ ] 6. **Scanner-rule manager — `/admin/scanners` (Phase 1, hardened with score-validation).** Versioned rules + scoring weights; the **score-validation gate** ([SPEC §6.5](../../SPEC.md) / M3b from [03-scanner-score-validation.md](03-scanner-score-validation.md)) required before publish; reason/label templates linted against the blocked-phrase list at save; four-eyes; every scanner result carries the rule-version ID ([admin §2.5](../20-admin-panel.md), [13](../13-scanner-engine-and-scoring.md)).
- [ ] 7. **Prompt manager + AI audit viewer — `/admin/prompts`, `/admin/ai-audit` (Phase 2, with the AI layer from [04-ai-explanation-layer.md](04-ai-explanation-layer.md)).** Versioned prompts pinned to the payload-contract schema; **eval-harness gate** on publish ([SPEC §6.6](../../SPEC.md)); the append-only AI audit log with verdict/grounding-mismatch/cost/latency, redaction-aware role-gated views ([admin §2.6–2.7](../20-admin-panel.md), [security §6](../23-security-auth-and-privacy.md)).
- [ ] 8. **User + subscription + news-source managers (Phase 2).** User ops + **right-to-erasure** execution; subscription tiers + the **SEBI fee-cap guard** for any future RA-operated tier ([SPEC §11](../../SPEC.md)); news-source reliability + sentiment-model + confidence-threshold config ([SPEC §6.4](../../SPEC.md)) ([admin §2.9–2.11](../20-admin-panel.md)). No admin view ever renders a secret in plaintext.
- [ ] 9. **Alert-delivery logs (Phase 2), backtest monitor (Phase 4), system-health dashboard (post-M5).** Alert bodies guardrail-checked + event-reporting-only ([admin §2.12](../20-admin-panel.md)); backtest integrity checklist gates publish ([SPEC §6.3](../../SPEC.md), [admin §2.13](../20-admin-panel.md), backtesting lands per the V5 sibling); system-health surfaces service tiles + the **hard AI-spend meter** reading the same gauge as observability ([admin §2.14](../20-admin-panel.md), [infra §6.1](../22-infrastructure-devops-and-observability.md)).
- [ ] 10. **Admin activity log (from the first state-changing module).** Append-only WORM-backed `admin_activity_log`; the write occurs in the **same transaction** as the action (no action without a log); author + approver IDs recorded on every publish ([admin §3](../20-admin-panel.md), [security §6](../23-security-auth-and-privacy.md)).

### Tests / Acceptance criteria
- [ ] A `support` user hitting any `*/publish` or rule-edit endpoint gets `403` and the attempt is logged; a self-approval gets `409 self_approval_forbidden` ([admin §1](../20-admin-panel.md)).
- [ ] Re-running a stage re-emits **all** dependent downstream artifacts for the affected symbols (no partial-state leak); a historical run shows the exact as-of + source versions ([admin §2.1–2.2](../20-admin-panel.md)).
- [ ] The compliance test-console output is **byte-identical** to runtime Stage-1 for the same input + version (CI parity test); the Tier-1 floor cannot be deleted/downgraded ([compliance §9](../21-compliance-risk-and-guardrails.md)).
- [ ] A scanner weight change cannot reach `published` without a passing validation run **and** a distinct approver; a prompt cannot publish without a passing eval run ([admin §2.5–2.6](../20-admin-panel.md)).
- [ ] Every state-changing admin endpoint fails if the activity-log write fails (enforced in middleware, tested) ([admin §3](../20-admin-panel.md)).

## Workstream: Compliance & guardrail operations
**When:** A **prototype-grade** guardrail + grounding check ships locally with [04-ai-explanation-layer.md](04-ai-explanation-layer.md) (M4); the **production three-stage pipeline + audit log** hardens in Phase 2; the design-review gate is in force from the **first** user-facing output (Phase 1); AI-use disclosure only **if/when Mode B** (Phase 5). · **Backend dep:** `compliance_rules` + `prompt_versions` loaded **by version** (hot-reloadable), the compliance-review agent (itself versioned + eval-gated), `ai_generation_audit` ([compliance §9](../21-compliance-risk-and-guardrails.md)) · **Frontend dep:** none for enforcement; admin test console ([admin §2.8](../20-admin-panel.md)) · **Data dep:** the structured payload contract from the AI layer ([04](04-ai-explanation-layer.md), [SPEC §6.6](../../SPEC.md))

### Steps
- [ ] 1. **Seed the blocked-phrase list (Phase 0 → 1).** Use the counsel-approved seed from [00-phase-0-derisk.md](00-phase-0-derisk.md) (Tier-1 always-prohibited + Tier-2 Mode-A) and the §5 swap table + the "candidate"-proximity rule ([compliance §3, §5.1](../21-compliance-risk-and-guardrails.md)).
- [ ] 2. **Local prototype guardrail (M4, with [04](04-ai-explanation-layer.md)).** Regex/pattern + number-grounding against the payload, **in the AI module**, with bounded regenerate → safe non-AI fallback / suppress on missing inputs ([SPEC §6.2, §6.6, §6.9](../../SPEC.md)).
- [ ] 3. **Production output-time pipeline (Phase 2).** Promote to the three stages — **Stage 1** regex/pattern (versioned list), **Stage 2** number-grounding (every number/fact ∈ payload), **Stage 3** compliance-review agent for *implied* advisory substance (substance over form, [compliance §13](../21-compliance-risk-and-guardrails.md)). `block` stops output; `regenerate` retries then falls back; `warn` ships + flags. The agent's own output also passes Stages 1–2 ([compliance §9](../21-compliance-risk-and-guardrails.md)).
- [ ] 4. **AI audit logging (Phase 2).** Every generation writes exactly one immutable record: prompt + prompt-version, input payload, model + model-version, **guardrail-version**, user-visible output (or block/suppress decision), verification verdict + grounding mismatches, cost + latency ([SPEC §6.6](../../SPEC.md), [admin §2.7](../20-admin-panel.md)).
- [ ] 5. **Design-review gate in the release process (from Phase 1).** Wire the 13-item compliance design-review checklist ([compliance §12](../21-compliance-risk-and-guardrails.md)) into PR review **and** the staging sign-off ([QA §3](../25-qa-testing-and-release-process.md)) for **every** new user-facing output (screen, prompt, scanner label, alert, brief, copy, SEO HTML). A "no" on any item blocks merge pending compliance-officer sign-off.
- [ ] 6. **Blocked-phrase list versioning + escalation (Phase 2).** Four-eyes change control on the list ([compliance §10.2](../21-compliance-risk-and-guardrails.md)); the escalation table ([compliance §11](../21-compliance-risk-and-guardrails.md)) wired to a review queue; a new SEBI circular triggers a version-bump + positioning re-eval.
- [ ] 7. **AI-use disclosure (Phase 5, Mode B only).** Build the **mandatory AI-use disclosure** into RA-mode onboarding + terms — a distinct obligation **not** satisfied by the generic "not investment advice" disclaimer ([SPEC §6.7](../../SPEC.md), [compliance §6 rule 8, §8](../21-compliance-risk-and-guardrails.md)). Lands with the RA-gated sibling ([14-v9-advisory-ra-gated.md](14-v9-advisory-ra-gated.md)); **not built locally**.

### Tests / Acceptance criteria
- [ ] No user-visible generated/templated output reaches the client without passing all three stages (enforced in the output path, tested in CI) ([compliance §9](../21-compliance-risk-and-guardrails.md)).
- [ ] A Tier-1 phrase is `block`ed regardless of admin config; an ungrounded number triggers regenerate/suppress and **never** ships ([SPEC §3.3, §6.6](../../SPEC.md)).
- [ ] Adversarial guardrail cases (paraphrases of "buy now", leetspeak, split tokens, multilingual, "candidate" near buy-lean signals) still block ([QA §1.4](../25-qa-testing-and-release-process.md)).
- [ ] Every verdict (`pass`/`block`/`regenerate`/`warn`) is in the AI audit log with rule + prompt + model version IDs ([compliance §9](../21-compliance-risk-and-guardrails.md)).
- [ ] Disclaimer is present where required **and** the substance is safe without relying on it (necessary-not-sufficient) ([compliance §8](../21-compliance-risk-and-guardrails.md)).

## Workstream: Testing & QA (test pyramid → SPEC validation gates)
**When:** Unit + integration + scanner-golden + data-quality + AI-grounding + guardrail stand up **early (Phase 1–2)** alongside [02](02-indicators-and-scanners.md)/[03](03-scanner-score-validation.md)/[04](04-ai-explanation-layer.md); API-contract with the API layer (Phase 1, M5); visual-regression + E2E with the Next.js UI; load + security (DAST) **pre-release** as the surface grows. · **Backend dep:** `pytest`/`vitest`, ephemeral DuckDB/Postgres, `schemathesis`, the verification harness, the guardrail engine ([QA §1](../25-qa-testing-and-release-process.md)) · **Frontend dep:** Playwright (after UI graduation) · **Data dep:** **frozen, committed, as-of-stamped fixtures** — never live vendor data in CI ([QA §2](../25-qa-testing-and-release-process.md))

### Steps
- [ ] 1. **Stand up the early pyramid (Phase 1).** Unit (indicators/scoring/adjusters — gates M2 reconciliation), integration (repo↔DB, pipeline stages, adapter↔storage), and **scanner-golden series** (locked score + exact Mode-A reason strings + exact risk-flag set; missing sub-score → **neutral**, not guessed) ([QA §1.1](../25-qa-testing-and-release-process.md), [02](02-indicators-and-scanners.md)).
- [ ] 2. **Data-quality tests (Phase 1, code + runtime).** Missing candles, abnormal jumps (= corp action, not bad data), duplicates, delisted, volume sanity, **second-source reconciliation** — driving detect→quarantine→correct→re-emit; a correction re-emits dependent indicators **and** AI summaries ([QA §1.2](../25-qa-testing-and-release-process.md), [SPEC §6.1–6.2](../../SPEC.md)).
- [ ] 3. **AI-grounding + guardrail tests (Phase 2, with [04](04-ai-explanation-layer.md)).** Payload-contract, number-traceability, suppression-on-missing-input, golden-dataset regression on every prompt/model change, audit-log test; the **guardrail layer is a hard blocker** over AI output, UI copy, and **rendered SEO HTML** ([QA §1.3–1.4](../25-qa-testing-and-release-process.md), [analytics §3.2](../24-analytics-seo-and-growth.md)).
- [ ] 4. **Build the test-data fixture sets.** Split/bonus/rights/symbol-change names (no false crash), delisted/merged names (survivorship), golden indicator series, missing/dirty data, AI golden payloads, and a blocked-phrase corpus (positive + adversarial + **negative to avoid over-blocking** legitimate descriptive copy) — all point-in-time/as-of stamped ([QA §2](../25-qa-testing-and-release-process.md)).
- [ ] 5. **Add the breadth layers as the surface grows.** API-contract (OpenAPI diff, M5), visual-regression + E2E (Playwright, post-UI), **load** (k6/locust — EOD-window + tier P95), **security** (SAST per-PR, DAST + dependency audit pre-release) ([QA §1](../25-qa-testing-and-release-process.md)).
- [ ] 6. **Backtesting-integrity tests (Phase 4).** Survivorship / look-ahead / point-in-time / realistic-fills — these are correctness **and** compliance tests; an inflated backtest is an implied-performance claim ([QA §0.3, §1](../25-qa-testing-and-release-process.md), [SPEC §6.3](../../SPEC.md)).
- [ ] 7. **Map every layer to a SPEC validation gate + release gate.** Correctness / Compliance / Economics / Trust — Compliance + Trust are **hard blockers**, Economics blocks pre-release ([QA §6](../25-qa-testing-and-release-process.md)).

### Tests / Acceptance criteria
- [ ] Every PR runs unit → integration → API-contract → scanner-golden → data-quality → AI-grounding → guardrail; a guardrail-test failure or a fabricated-number regression **fails the build** ([QA §0.2, §1](../25-qa-testing-and-release-process.md)).
- [ ] Staging sign-off requires: full E2E green, harness green, guardrail green over rendered output + SEO HTML, data-quality + reconciliation green, **compliance design-review recorded**, load targets met ([QA §3](../25-qa-testing-and-release-process.md)).
- [ ] CI uses frozen fixtures only; reproducibility is testable via as-of stamps ([QA §2](../25-qa-testing-and-release-process.md)).
- [ ] The four SPEC gates (correctness/compliance/economics/trust) each map to ≥1 test layer and a documented release gate ([QA §6](../25-qa-testing-and-release-process.md)).

## Workstream: Infra & cloud graduation (local-first → AWS)
**When:** **Local-first only** through Phase 0–1 / local M0–M5 (DuckDB, **no Docker, no cloud** day one — [SPEC §9, §12](../../SPEC.md)); **graduation trigger = local M5 retires the three product-killing assumptions** ([SPEC §12](../../SPEC.md), [infra §8](../22-infrastructure-devops-and-observability.md)); then containerize → Terraform the AWS stack → CI/CD with compliance gates → observability + AI-spend meter → staging/prod → rollback → DR (Phases 2+). · **Backend dep:** the local modules from [01-local-mvp-foundation.md](01-local-mvp-foundation.md) lift 1:1 into services · **Frontend dep:** CloudFront/CDN once the Next.js UI exists · **Data dep:** signed licensed-vendor contract with redistribution rights before production data ([SPEC §8](../../SPEC.md))

### Steps
- [ ] 1. **Hold the line locally (Phase 0–1).** Run the MVP on one M1 Mac with DuckDB; provide `docker-compose.yml` **but do not run it**; **no cloud spend, no RA-gated feature built locally** ([SPEC §12](../../SPEC.md), [infra §3](../22-infrastructure-devops-and-observability.md)). State the trigger explicitly in the decision log: cloud begins **only after M5**.
- [ ] 2. **Containerize (post-M5).** Docker images per service (API, worker, AI worker), multi-stage, distroless/slim, pinned digests, non-root, **ARM64-friendly, no TA-Lib** (matches the M1 story) ([infra §2](../22-infrastructure-devops-and-observability.md)).
- [ ] 3. **Terraform the AWS stack (post-M5).** VPC/subnets, RDS Postgres + TimescaleDB (**as-of versioned**), ElastiCache Redis, S3 (object-lock for WORM audit), ECS Fargate (→ EKS at scale), API Gateway, Lambda, EventBridge, SQS+DLQ, WAF, Secrets Manager, CloudWatch — **no console drift**; state in S3 + DynamoDB lock; envs differ only by `tfvars` ([infra §1–2](../22-infrastructure-devops-and-observability.md)).
- [ ] 4. **EOD-batch scheduling.** EventBridge cron post-close → SQS-decoupled stages (ingest → normalize → corp-action adjust → indicators + sector → scanners → news → AI → guardrails → morning brief); progress streams to the ingestion monitor; a missed overnight SLO alerts **before market-open** ([infra §5](../22-infrastructure-devops-and-observability.md), [SPEC §6.8, §8](../../SPEC.md)).
- [ ] 5. **CI/CD with the compliance-critical gate.** lint/type → unit → **AI eval-harness + guardrail-parity** → image build + SCA/secret scan → ECR → Terraform plan (gated apply) → staging → smoke → gated prod (blue-green API / canary AI-worker) → post-deploy verify. A change to AI prompts, scanner scoring, or compliance rules **cannot reach prod** unless the eval + guardrail-parity jobs pass ([infra §4](../22-infrastructure-devops-and-observability.md), [SPEC §6.6, §6.9](../../SPEC.md)).
- [ ] 6. **Observability + the hard AI-spend meter.** OpenTelemetry → Prometheus/Grafana + Sentry + CloudWatch (same source as the admin system-health dashboard); the **hard monthly AI-spend ceiling** as a first-class gauge with 70/85/100% alerts, burn-rate/projection, and **graceful degradation** (cached/non-AI fallback) at the ceiling ([infra §6, §6.1](../22-infrastructure-devops-and-observability.md), [SPEC §6.8](../../SPEC.md)).
- [ ] 7. **Environments + rollback + DR.** local → staging → production (RA features flag-absent from the v1 router); **feature-flag-first rollback** + prior image + prior prompt/rule versions; auto-rollback on SLO breach; DR with PITR, WAL/snapshot archive, object-lock audit, and a quarterly **DR drill that replays a batch and reconciles vs a second source** ([infra §3, §4.1, §7](../22-infrastructure-devops-and-observability.md), [QA §4.1](../25-qa-testing-and-release-process.md)).

### Tests / Acceptance criteria
- [ ] **No cloud resource is provisioned before M5 sign-off** ([SPEC §12](../../SPEC.md)); the trigger is recorded in the [decision log](../30-decision-log.md).
- [ ] All cloud resources are Terraform-managed; `terraform plan` is clean post-apply; environments differ only by `tfvars` ([infra §2](../22-infrastructure-devops-and-observability.md)).
- [ ] The overnight batch completes within budget on the full universe; a failed stage re-emits only its affected downstream artifacts; every artifact carries its as-of version ([infra §5](../22-infrastructure-devops-and-observability.md)).
- [ ] Crossing 85% AI-spend raises an alert; crossing 100% engages documented graceful degradation (no silent overspend); the meter and admin dashboard read the **same gauge** ([infra §6.1](../22-infrastructure-devops-and-observability.md)).
- [ ] A region-loss DR drill restores core read paths within RTO; audit logs are provably immutable (object-lock); a restored env reproduces a prior day's displayed values exactly ([infra §7](../22-infrastructure-devops-and-observability.md)).

## Workstream: Analytics & trust KPIs (+ Mode-A SEO)
**When:** Event schema + **trust KPIs** instrumented **at launch (Phase 1–2)** as the headline metrics; the public SEO pages with the AI/scanner surfaces they describe (Phase 1–3, Mode-A-safe). · **Backend dep:** `/api/v1/analytics/collect`, server-side schema validation, nightly EOD-aligned dbt transforms → trust/engagement/funnel/retention marts ([analytics §1](../24-analytics-seo-and-growth.md)) · **Frontend dep:** analytics SDK (consent-gated, batched, idempotent) + the public SSG/ISR pages ([analytics §1.4, §3](../24-analytics-seo-and-growth.md)) · **Data dep:** AI surfaces carry `grounded`/`model_version`/`audit_id`; trust events carry `as_of`/`trading_date` ([analytics §1.3](../24-analytics-seo-and-growth.md))

### Steps
- [ ] 1. **Event envelope + canonical catalog (Phase 1–2).** The common envelope (pseudonymous `user_id`, `trading_date`/`as_of`, `consent`) + the catalog; **server-side schema validation** with dead-letter + alert on unknown/invalid events (no silent drops) ([analytics §1.1–1.4](../24-analytics-seo-and-growth.md)).
- [ ] 2. **Instrument the trust events as primary KPIs.** `data_error_report`, `insight_useful`, `insight_disagree` — plus `ai_query`/`ai_summary_view` carrying `grounded`/`model_version`/`audit_id` (link every AI analytics row back to the audit log) and `refused` as a **healthy** compliance signal ([analytics §1.2–1.3](../24-analytics-seo-and-growth.md)).
- [ ] 3. **Trust marts + the T1–T5 KPIs.** Compute nightly: T1 incorrect-data reports (↓), T2 mark-insight-useful (↑), T3 disagree-with-AI (↓, investigate spikes), T4 grounding rate (↑ near-100%), T5 refusal correctness. **T1-rise / T4-drop is a stop-the-line** alert that outranks any growth target; growth KPIs are explicitly subordinate ([analytics §2](../24-analytics-seo-and-growth.md), [QA §4.2](../25-qa-testing-and-release-process.md)).
- [ ] 4. **No PII in analytics (privacy by design).** Hashed `user_id`, no email/holdings/symbol-amounts in `props`; free-text reports stored separately (only `note_len` in events); consent-gated; raw events 13-month retention ([analytics §1.6, §0.4](../24-analytics-seo-and-growth.md), [security §5](../23-security-auth-and-privacy.md)).

## Workstream: Security & privacy hardening (phased with features)
**When:** Auth/RBAC + secrets + encryption with accounts and the cloud graduation (Phase 2); PII/erasure with user management (Phase 2); AI-log security with the AI layer (Phase 2); broker-token isolation only at Phase 5+. **No security theater locally** — the local prototype has no real users/secrets beyond `ANTHROPIC_API_KEY` in env. · **Backend dep:** JWT/OIDC auth, the RBAC matrix ([admin §1](../20-admin-panel.md)), Secrets Manager, KMS, the erasure workflow ([security](../23-security-auth-and-privacy.md)) · **Frontend dep:** MFA flows, consent UI · **Data dep:** PII fields envelope-encrypted; portfolio holdings treated as PII-class

### Steps
- [ ] 1. **Authentication (Phase 2).** Short-lived signed (RS256) JWT + rotating revocable refresh tokens with reuse detection; OAuth/OIDC social sign-in; TOTP for users + **hardware-MFA enforced for super-admin**; Argon2id + breach-list passwords; rate-limited login with lockout ([security §1](../23-security-auth-and-privacy.md)).
- [ ] 2. **Authorization (Phase 1–2).** Row-scope every user read (no IDOR, ownership checked server-side); the five-role RBAC matrix via `can(...)` middleware with **four-eyes** on compliance/prompt/scanner publishes; tier entitlements as an authz check **in-route** (not separate URLs); least-privilege service IAM + DB grants ([security §2](../23-security-auth-and-privacy.md), [admin §1](../20-admin-panel.md)).
- [ ] 3. **Secrets & encryption (with cloud graduation).** Secrets Manager only (DB creds, `ANTHROPIC_API_KEY`, vendor keys, future broker tokens) — **never** in code/images/logs; scheduled zero-downtime rotation (super-admin-only trigger, logged); TLS 1.2+ in transit; KMS at rest; **application-level envelope encryption** for sensitive PII ([security §3–4](../23-security-auth-and-privacy.md), [infra §1](../22-infrastructure-devops-and-observability.md)).
- [ ] 4. **PII protection + right-to-erasure (Phase 2).** Minimal collection; portfolio holdings as PII-class (encrypted, row-scoped, redacted from logs, only the structured non-advisory payload to the LLM); erasure removes/anonymizes PII while retaining legally-minimal anonymized compliance records; erasure is itself logged; prefer India/region-appropriate residency (confirm with counsel) ([security §5](../23-security-auth-and-privacy.md)).
- [ ] 5. **AI-log security (Phase 2).** The AI audit log is **PII-bearing and immutable** — append-only WORM/object-lock; **redaction at write** (not just display); full raw-payload view restricted to `compliance-officer` + `super-admin`, redacted for `support`/`read-only`; defined retention window ([security §6](../23-security-auth-and-privacy.md), [SPEC §6.6](../../SPEC.md)).
- [ ] 6. **Network/app hardening + the per-change checklist.** WAF (OWASP + rate-based, strict `/admin/*` + `/api/*` rules), per-IP/per-user rate limits (stricter on auth + AI endpoints — ties to the AI-spend meter), schema validation + parameterized queries + XSS/CSRF; **prompt-injection defense = the grounding contract itself** (AI references only the structured payload). Run the 12-item security checklist per change ([security §7, §9](../23-security-auth-and-privacy.md), [SPEC §6.6, §6.8](../../SPEC.md)).
- [ ] 7. **Broker-token isolation (Phase 5+ only).** When broker integration lands (Mode B/C), tokens are envelope-encrypted, short-scoped, revocable per user, never logged, isolated from the general user store — highest-sensitivity class ([security §7](../23-security-auth-and-privacy.md)). Not built before Phase 5.

### Tests / Acceptance criteria
- [ ] Tokens are short-lived + revocable; a stolen refresh token is self-revoking; no endpoint accepts an unsigned/expired JWT; passwords Argon2id + breach-checked ([security §1](../23-security-auth-and-privacy.md)).
- [ ] IDOR test suite: a user cannot access another user's objects; admin actions resolve through the RBAC matrix; self-approval rejected (`409`) ([security §2](../23-security-auth-and-privacy.md)).
- [ ] No secret appears in source/images/logs (CI secret-scan); rotation completes without downtime and is logged ([security §3](../23-security-auth-and-privacy.md)).
- [ ] An erasure request completes within SLA; post-erasure no PII is retrievable except the minimal anonymized compliance record; portfolio data never in plaintext logs ([security §5](../23-security-auth-and-privacy.md)).
- [ ] The AI log is provably append-only + tamper-evident; raw payloads visible only to authorized roles; redaction runs at write time ([security §6](../23-security-auth-and-privacy.md)).
